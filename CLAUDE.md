# Indy's Year — project notes for Claude Code

Personal fitness + weight + blood-sugar tracker for one user (NZ mum, postpartum, type 2 diabetes / prediabetes).
Goals: −5 kg in 3 months, −15 kg by Indy's first birthday, HbA1c into the NZ non-diabetic range (under 42 mmol/mol).

## Stack (keep it this way)
- Single-file app: `index.html` (all CSS + JS inline, no build step, no frameworks). External code is limited to two pinned jsDelivr files, both loaded lazily and cached by `sw.js`: the supabase-js UMD (SRI hash) and, only when the browser has no native `BarcodeDetector` (iOS Safari), the `barcode-detector@2.3.1` ES module (`ZXING_SRC`; a dynamic `import()` cannot carry SRI, so keep it pinned to an exact version), which itself fetches its ZXing WASM from `fastly.jsdelivr.net`. `sw.js` caches every `*.jsdelivr.net` host at runtime in the unversioned `indys-year-cdn` cache (so releases don't discard the offline scanner); if you change either pinned URL, nothing else needs updating, but keep the supabase-js `SB_JS` in `sw.js` in step with `SB_SRC`. If you bump it, update the version + SRI in `index.html` (`SB_SRC`/`SB_SRI`) and `SB_JS` in `sw.js`.
- `sw.js` offline cache, `manifest.webmanifest`, icons. Static hosting over HTTPS on Vercel (`vercel.json` sets headers; `robots.txt` blocks indexing).
- Storage: IndexedDB (`indy-tracker` db, `kv` store, key `state`) with localStorage mirror (`indy-tracker-v1`).
- Data schema is backward-compatible with the v1 backup JSON. Never break `migrate()`.

## Rules
- Bump `VERSION` in `sw.js` on every change to `index.html`, then commit and push (Vercel auto-deploys from `main`).
- Deterministic analytics only (no AI calls). NZ units: kg, cm, mmol/L, mmol/mol.
- Safety thresholds live in `insights()` and `preStart()` in index.html. Do not loosen: breastfeeding pace cap 0.5 kg/wk, hypo < 3.9 mmol/L, NZ HbA1c bands under 42 / 42–47 / 48+ (Health NZ, in force from 1 July 2026, replacing the old 40/41–49/50+; confirmatory test advised at 48–52). These bands live in `hbCat()`, the Home band markers (`t42`/`t48`), the Insights and report HbA1c charts, the copy, and the report footer: change them together.
- No remote images or tracking. Exercise figures are inline SVG poses in `POSES`.
- Fonts (Chakra Petch for headings/numbers, Barlow for body) are self-hosted in `/fonts` as custom subsets (Latin, Latin Extended-A, arrows, ≈) with the OFL licence in `fonts/LICENSE.txt`. No Google Fonts or other font CDN. Any font file added or renamed under `/fonts` MUST be added to the `FILES` list in `sw.js` (and `VERSION` bumped) or it won't work offline. Chakra Petch is Barlow's fallback so the arrow glyphs resolve.
- Visual style is "Neon Athletic": all colour comes from `--accent`, glow uses `--glow`/`--tglow`, and both are switched off in light mode. Don't hard-code colours; keep all 8 themes + custom colour + light/dark working.
- Not medical advice; never add medication-dose advice.
- Food tab (offline food database, manual entry, protein quick-log, calorie/protein targets from age/height/weight): data lives in `S.meals` (array of {id,d,meal,name,g,kcal,p,c,f,fb,src}) and `S.foodCache` (object keyed by barcode). Barcode scanning uses the native `BarcodeDetector` when present, otherwise the pinned polyfill (`getDetector()`), with manual code entry as the last fallback; the first polyfill scan needs a connection (about 1 MB of WASM), after which it works offline and looks the code up on Open Food Facts (`https://world.openfoodfacts.org/api/v2/product/<code>.json`). That user-initiated lookup is the only network call besides Supabase and the pinned supabase-js CDN script; results are cached in `S.foodCache`. `vercel.json` sets `Permissions-Policy: camera=(self)` (not `camera=()`) so the scanner can use the camera; there is no Content-Security-Policy, so no `connect-src` to maintain (add `https://world.openfoodfacts.org` there if one is ever introduced).
- Big food database: `foods.json.gz` (~11,300 foods: USDA SR Legacy + Foundation, AUSNUT 2023, with US fast-food chains and "Restaurant," entries dropped by `DROP_FASTFOOD` in the build script; per 100 g; ~370 KB) is precached by `sw.js`, lazy-loaded by `loadBigDB()`, kept in IndexedDB (`indy-fooddb`, NOT in `S`, NOT synced) and searched by `bigSearch()`. The loader detects gzip by magic bytes, so it works whether or not the server sets Content-Encoding. When you rebuild it with `tools/build_fooddb.py` (see `tools/README.md`) you MUST bump `FOODDB_VER` in `index.html` and `VERSION` in `sw.js`, otherwise phones keep the old copy. Attribution (USDA; AUSNUT 2023, CC BY 4.0 AU; Open Food Facts, ODbL) is shown in the About card; keep it.
- Move tab (`viewActivity`/`bindActivity`, script section "Activity"): manual activity log and a GPS walk/run tracker (Geolocation + Wake Lock, shown only while the sheet is open). Only the summary (min, km, kcal, elevation, pace) is saved into `S.activity`; the route itself is never stored or synced and is not even kept in memory (only a count of fixes and the last point). Deleting an activity must use `dropWhere` (the Move tab does). Running is gated by `runUnlocked()` (postpartum return-to-run check sets `profile.runOK` and stamps `profile.updatedAt`; auto-unlocks at 52 weeks) and is re-checked in `startGPS()`. `vercel.json` sets `Permissions-Policy: geolocation=(self)`. The streak is forgiving ("never miss twice": it breaks after 2 inactive days in a row).
- Exercise picker (Move tab and + sheet, `manualActivitySheet(d0)`): search `EXDB` (77 exercises with Compendium MET values, `searchEx()`), pick, enter minutes; unlisted names fall back to a custom entry (4.0 MET, name capped at 60 chars, flagged "rough"). Records are `{kind:"ex", name, min, kcal}` with `kcal = kcalMET(met, min, kg)`; the list shows `a.name`. `kcalFor` (GPS tracker, post-meal walks) is separate and unchanged. Old records with `kind` walk/pram etc. still display via `ACT_TYPES`.
- Apple Health import (Log > Import): the Shortcut (named "Capture my health") ends with Copy to Clipboard, and the **Paste from clipboard** button reads it with `navigator.clipboard.readText()` and calls `importHealthText()` (also used by the paste-by-hand box; it tolerates URL-encoded text and a pasted `https://…#weight=…` link). Do NOT point people at an "Open URLs" step: on iPhone that can open Safari, which keeps separate storage from the Home Screen app, so the numbers would not reach her data (the boot-time `#hash` import still exists but only works in the same storage context). The weight step must use "Start Date is today" or an old weigh-in is logged as today's. `applyKV()`: `applyKV()` parses weight, steps, exercise minutes (kcal estimated via `kcalFor`), resting heart rate and sleep hours. Heart rate and sleep go into `S.vitals` ({id,d,hr,sleep,src}); each value is range-checked separately (hr 26-159; sleep via `sleepHours()`: under 24 = hours, 24-1440 = minutes, above that up to 86400 = seconds, converted to hours and rejected if not under 24 h). Imports are idempotent upserts: one Apple Health row per type per NZ day, updated in place (same id) by `applyKV()`; `dedupeState()` (run by `migrate()` and `mergeStates()`) collapses exact duplicates (weights any source; Apple Health activity/vitals) to the lowest id and tombstones the rest, so devices converge. Manual weights refuse an exact same-day/same-value repeat. Steps live on the Apple Health activity record (`steps`); `daySteps(d)` sums per NZ day and returns null (shown as —) when none. Schema is v4 (`vitals` array; `migrate()` adds it to older states). Insights shows a "Sleep & heart rate" card when there are vitals in range. Viewers can see vitals (the whole state is readable by anyone you share with).
- Keep screen on (You tab): `keepAwakeOn` + Wake Lock, re-acquired on `visibilitychange`; `wake(false)` does not release it while the toggle is on. Not persisted across app restarts.
- Selector trap: `<html>` carries `data-mode` (set by `applyTheme`), so never use an unscoped `$$("[data-mode]")`; the Light/Dark buttons use `button[data-mode]`. (Unscoped, `<html>` got the button's click handler and every click re-rendered the page and reset "Match phone".)
- UX conventions (a deliberate simplification pass; keep them): **Home is "Today"** (quick-log row Weight/Glucose/Food/Walk, trend, rings, workout, ONE "Today's habits" card, blood sugar; about 1.5 screens: do not re-add the heatmap or insight card, they live in Insights). **One logging entry point:** the floating + (`#fab`, `openAddSheet()`) on every main tab opens Weight, Glucose, Measurements, HbA1c, Activity, Food, Apple Health; **every form lives in a sheet** (`weightSheet`, `glucoseSheet`, `measuresSheet`, `hba1cSheet`, `manualActivitySheet`, `addFoodSheet`, `healthSheet`) and is never duplicated elsewhere (duplicate ids would break). Weight is pre-filled with her last weight, dates default to today (`formDate()` refuses silly dates), every field shows its unit. **You** is six collapsible sections (open state kept in `YOUOPEN`); goals and safety **auto-save on change** (`profilePatch()`; never add a mid-page Save button; an impossible starting weight is put back). Insights: Summary / Weight / Sugar / Training, "This week" is plain progress bars (no score), the nine tips sit in one folded "Learn" card. Plain language: no "kcal/day deficit" on Home; the Move tab is called Move. A first-week **Getting started** checklist (`profile.createdAt`, `hideStart`, `checklist`; folds after 2 days, gone after 7) is hidden for viewers.
- Accessibility rules (tested in `ux-test`-style sweeps at 390/360/320px): every tap target at least 44x44px (checkbox rows are `label.toggle`), no text under 12px (the Train day grid uses `auto-fill minmax(44px,1fr)`), toasts are at the top (`top:10px`), and all 8 themes in both modes meet WCAG AA for dim text, chips and button text (light-mode amber is `#AD4F08`: do not lighten it). When you add a colour, re-check it against `--surface-2`.
- Data hygiene: `migrate()` ends with `sanitizeState()`, which every state from storage, a backup file, the cloud or a shared viewer account passes through (numbers range-checked, ids/kinds/theme reduced to plain tokens, dates clamped to 2000-01-01..a year ahead, theme colour must be #rrggbb, junk tombstones dropped, tombstones older than 400 days pruned). **If you add a field that is shown in HTML or used in a calculation, add it to `NUMSPEC`/`sanitizeState` too** (a hostile shared state could otherwise run script in a viewer's browser). Still `esc()` free-text strings.
- Sheets and timers: `sheet()`/`closeSheet()` run `sheetCleanup` (the barcode scanner registers its camera shutdown there) and closeSheet stops a running walk timer. The backdrop does not close a sheet while a walk is timed or GPS is tracking. GPS live numbers update in place (`updGPS`), never by rebuilding the sheet. The debounced save is flushed on `visibilitychange`→hidden and `pagehide` (`flushSave`), and Home re-renders after midnight (`RENDER_DAY`).
- Known limitations (reviewed, deliberately left): "Erase all data" while signed in can let ticked pelvic-floor days / protein dots return from another device (they are merged as a union and have no timestamps); sessions and vitals have no delete screen.
- Tabs: Home, Train, Food, Move, Insights, You (6 tabs; viewers only see Home, Insights, You). Log is a history screen reached with `openLog(seg,from)` (You > Data & backup, or "See all …" links inside the forms); it is not a tab, shows the tab she came from as highlighted (`LOGFROM`), has a Back button, lists the latest 10 per section with Show all, and has no forms of its own. Insights has date-range filters and a printable report (`reportHTML`, opened via the Report button). Setup has an age field.

## Deploy
Hosted on Vercel (project `indys-year`, framework Other, no build, output dir `.`), auto-deploys from the private GitHub repo `indys-year` on every push to `main`. First install: open the production URL in Safari on iPhone → Share → Add to Home Screen.

## Cloud sync (Supabase) — project "fitness", ref `rexnqtgodowbwjdvmudm`, region Seoul
Use ONLY this Supabase project. Never touch the user's other Supabase projects (Buildup, WorkUp, ...).
IndexedDB stays the primary store; Supabase is backup + merge-sync + read-only sharing. The app works fully offline and signed out.
- `SUPABASE_URL` / `SUPABASE_KEY` (publishable key, safe to commit) are at the top of the script in `index.html`. Never commit a secret/service_role key or an account token.
- Auth: email + password (`signUp` / `signInWithPassword`, min 8 characters, `updateUser` to change it). "Confirm email" is OFF in the Supabase dashboard, so **no email is ever sent** and no SMTP is needed; if it is turned on, sign-up will return no session and the app shows an error. There is no password reset (it would need email): reset a password in the dashboard under Authentication > Users. The password is never stored by the app; the supabase-js session persists in localStorage key `indy-sb-auth`, and `indy-sync-meta` remembers who is signed in.
- Schema: `supabase/migrations/20261005000000_app_state_and_viewers.sql`
  - `public.app_state(user_id uuid pk -> auth.users, state jsonb, updated_at timestamptz)` — one row per user holding the whole `S` object.
  - `public.viewers(owner_id uuid -> auth.users, viewer_email text, pk(owner_id, viewer_email))` — the share list (emails stored lowercase).
- RLS (both tables enabled; policies use `(select auth.uid())`):
  - app_state: owner select/insert/update/delete where `user_id = auth.uid()`; viewers select where a `viewers` row has `owner_id = app_state.user_id` and `viewer_email = auth.jwt()->>'email'`.
  - viewers: owner all where `owner_id = auth.uid()`; plus "viewer sees own invite" select where `viewer_email = auth.jwt()->>'email'` (needed, otherwise RLS hides the viewers table inside the app_state viewer policy).
- Merge design (`mergeStates`, `syncNow` in `index.html`) — merge, never overwrite:
  - Every record has an `id`. Deleting uses `dropWhere(arrayName, predicate)` (arrays in `ARR_KEYS`: weights, measures, glucose, hba1c, activity, sessions, meals, vitals; add any new array of records there and the sync, restore, wipe and migrate code all pick it up), which writes `S.deleted[id]=timestampMs` tombstones (pruned after 400 days). Any new code that removes a record MUST use `dropWhere`.
  - Arrays (weights, measures, glucose, hba1c, activity, sessions): union by id, minus ids in either side's tombstones. `foodCache`: union by barcode key (no deletes, local wins). `pf`: union. `protein`: per-date max (so un-ticking pf/protein on a synced account does not stick). Profile: the side with the newer `profile.updatedAt` wins (set it whenever the profile is saved); wiping sets `profileCleared`.
  - Sync = pull own row, merge, then push only if the cloud copy differs, using compare-and-swap on `updated_at` (retries up to 4x). Triggers: launch, sign-in, `visibilitychange`→visible, `online`, and 2 s after any `commit()`. Offline or failed syncs are silent and never block the UI or lose local data.
  - Viewer mode (`RO`): a signed-in user with no own row and no local data who can read another user's row sees that person's Home + Insights read-only (banner, no log/edit tabs, nothing persisted locally; `commit()`/`persistNow()` are no-ops).
- Home refresh and day logic: `commit()` queues a refresh of Home and sync pulls call `refreshView()` (held back while typing or in a workout, flushed on focusout). `iso()` with no argument is today in Pacific/Auckland. The weekly strength target is `STRENGTH_TARGET` (2–3 days; `strengthTxt`/`strengthFill`), shared by Home, Insights and the nudge. Insights has a Day view (`insDay`, `INDAY`).
